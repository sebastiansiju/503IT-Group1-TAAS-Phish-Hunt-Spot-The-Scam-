## 1. Overview

During Week 02 Session 02, our group finalised the development direction for our cyber‑safety game *Phish Hunt: Spot the Scam*. This session focused on selecting the most suitable development tool, refining our concept, analysing repository structure, and preparing for Prototype Version 1. Our decisions were based on user needs, project requirements, and the goal of creating a realistic phishing‑simulation experience for teenagers aged 15–16.

---

## 2. Final Tool Selection

After comparing **Scratch** and **Visual Studio Code**, we selected **VS Code** as our primary development tool.

### Why VS Code Was Selected
- Supports **HTML, CSS, JavaScript** for realistic web‑based phishing simulations.  
- Allows full control over layout, colours, buttons, and interactive behaviour.  
- Professional debugging and testing tools.  
- Suitable for creating **authentic email/message interfaces** teenagers recognise.  
- Integrates smoothly with GitHub for version control.  
- Meets all project requirements: realism, interactivity, accessibility, and scalability.

### Why Scratch Was Not Selected
- Too childish for our target audience.  
- Limited design and customisation.  
- Cannot create realistic phishing emails or web pages.  
- No HTML/CSS/JS support.  
- Not suitable for professional‑looking cybersecurity simulations.

---

## 3. Updated Concept Direction

Based on our Week‑2 concept development:

- The game will focus on **phishing awareness**, including suspicious links, fake messages, and smishing.  
- Scenarios will be designed to look like **mobile messages**, as teens primarily use phones.  
- The game will include **SAFE / SCAM** buttons, instant feedback, and a simple scoring system.  
- Visual style will replicate familiar social‑media and messaging UI layouts.

---

## 4. Prototype Version 1 – Planned Features

Prototype V1 will include:

- A **Start Screen** with game title and “Start Fishing!” button.  
- A **fake phishing message** (mobile‑style layout).  
- **SAFE / SCAM** interactive buttons.  
- **Instant feedback** explaining red flags.  
- A **simple scoring or success message**.  
- Clean, readable **HTML/CSS layout** suitable for teenagers.

This aligns with the storyboard and updated Game Concept Canvas.

## 7. Development Workflow (VS Code)

Our workflow for building Prototype V1:

1. Create project folder in VS Code.  
2. Build `prototype-v1.html` using semantic HTML.  
3. Add CSS for layout, colours, and readability.  
4. Add JavaScript for button interactions and feedback.  
5. Test in multiple browsers (Chrome, Edge).  
6. Capture screenshots for evidence.  
7. Upload HTML + screenshots to GitHub.  
8. Update contribution logs and meeting minutes.
